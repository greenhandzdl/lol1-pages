# lol1.moe · 萝莉图鉴

一本关于 12 位幻想小小居民的静态图鉴。全年龄、SFW、无广告、无追踪。

线上地址：<https://lol1.moe>

## 这是什么

- 12 位原创角色，每人 300–370 字长档案 + 一段「小场景」+ 「她的一天」四段时间线，
  外加地域、喜好、小习惯、以及一张可点击的关系网（共 38 条有向关系）
- 搜索、**主题筛选**、排序、收藏、地域视图、关系网全景、每日一抽、**此刻**（按时段看她们在做什么）
- 明暗双主题、详情弹窗、URL 状态同步（可分享 `?id=sakura`、`?tag=书`）
- **每人一套 accent 色 + 元素图形**：角色页、卡片、地域、关系网、3D 台都跟着 palette 走
- 纯静态、零构建、零第三方脚本、无 Cookie
- **3D 手办台**（`/3d/`）：拖拽旋转、双指缩放、键盘操作，外加一局「寻星」小游戏
- **收藏册**（`/shelf/`）：看过 / 收藏 / 转过 / 通关四类进度，未解锁显示剪影
- **小游戏**（`/play/`）：性格测试「你的邻居是哪位」+ 地名配对

## 技术栈

HTML + CSS + Vanilla JS（ES modules）+ 一份 JSON 数据。没有框架、没有构建步骤、没有 CDN。

> accent 与图形的对比度是算出来的，不是手写：浅 palette（#ffd9e6 对白底 1.3:1）
> 不能直接当文字色，`accent.js` 按 WCAG 压到 4.6:1 以上才输出 `--pa-ink`；
> 深色主题另有一个 `--pa-glow`。改 palette 之后跑一遍测试就能看到新对比度。

## 构建脚本

```bash
npm run check:data   # 校验 characters.json（关系指向、重名、文件存在、主题覆盖）
npm run img          # 重出插画 400/600 档（源图 mtime 未变则跳过）
npm run pages        # 重生成 c/<id>/ 12 个角色页 + 首页 noscript 兜底 + sitemap + feed
npm run release      # check:data → pages → 全量测试，发布前一条命令

# 改了 .glb 之后重渲 3D 缩略图（产物进仓库，不进 CI）
TEST_VENV=/path/to/venv ./scripts/build-model-thumbs.py            # 全部
TEST_VENV=/path/to/venv ./scripts/build-model-thumbs.py sakura mint  # 只渲指定的
```

改了 `characters.json` 之后记得跑 `npm run pages`，并把 `c/` 一起提交 ——
GitHub Pages 不跑构建，产物必须入仓。

### check-data 挡什么

内容变厚之后字段一多就容易写错，而有些错在页面上不一定看得见：

- **关系指向不存在的 id** —— 那张关系卡片会静默消失
- **名字重复** —— 扩写时复制粘贴忘改，最容易犯
- **图片/模型路径拼错** —— 线上 404，只有控制台有提示
- **主题不在词表里 / 某个主题人太少** —— 首页筛选项点下去只剩一张卡
- **story 和 bio 大面积重合** —— 复制粘贴的痕迹
- **「她的一天」不是四段或时段乱序**

另外会检查关系是否双向。单向不算错（有人单方面认为是朋友反而有故事），
所以只提醒不拦截。

### 主题（首页筛选词表）

首页芯片筛的是 `themes`，不是 `tags`。原因很直接：

`tags` 是身份标签，12 个人一共 35 个，其中 34 个只对应一个人。
点一个标签等于点名，筛出 1 张卡 —— 那不是筛选，是快捷方式。

`themes` 是一份受控词表（7 个主题，每人 2–3 个，每个主题至少 3 人）：

| 主题 | 人数 | 谁 |
| --- | --- | --- |
| 花与四季 | 4 | 樱井小春、雪乃、夜宵、花音 |
| 星光与咒语 | 3 | 星野澪、铃鹿、夜宵 |
| 茶与甜点 | 3 | 薄荷、茶茶、奶油 |
| 书页与静默 | 4 | 星野澪、茶茶、书织、雪乃 |
| 海风与高处 | 3 | 薄荷、小海、云雀 |
| 街角的熟客 | 4 | 铃鹿、小海、夜宵、奶油 |
| 认真做一件小事 | 6 | 樱井小春、茶茶、书织、花音、奶油、云雀 |

`tags` 仍然保留：它参与搜索、也进角色页的 `knowsAbout` 结构化数据，
只是不再当筛选项。旧分享链接 `?tag=书` 会回退成按标签筛，不会变成空白页。

### 关掉 JS 也能读

首页三块（图鉴 / 地域 / 关系网）都是 JS 渲染的。`build-pages.mjs` 会把
纯 HTML 摘要写进 `index.html` 里带 `data-build="…"` 标记的 `<noscript>`：

- `gallery` —— 主题分组 + 12 张带 `srcset` 的卡片
- `regions` —— 地域 → 角色链接
- `web` —— 38 条有向关系，一行一条

只替换标记内的内容，其余（手写正文）一概不碰；标记缺失时脚本报错退出，
不会静默追加。浏览器开着 JS 时 `<noscript>` 内容按原始文本处理、不进 DOM，
所以不需要 `aria-hidden`。

### 插画档位

插画原图 768×1024，另有 400w / 600w 两档供 `srcset` 选。

- **为什么不导 -768**：原图本来就是 768，再导一份实测只小 2KB，白多 12 个文件
- **为什么不用 AVIF**：实测 400px 档 AVIF 反而比 WebP 大（44.7KB vs 39.9KB），
  小尺寸下 AVIF 的头开销盖过了压缩优势

实测收益（DPR3 手机，同批 3 拍立得 + 4 卡片）：722KB → 427KB，省 41%。

## 本地存档

所有"你做过的事"存在 `localStorage` 的 `lol1:save` 一个键里，带版本号，
由 `assets/js/store.js` 统一管理。

```
{ v: 2, favs: [], seen: [], turned: [], spun: {}, stars: {} }
```

- `seen` 看过档案（打开详情或访问角色页）
- `turned` 在 3D 台真的转过（模型加载成功才算，立牌回落不算）
- `spun` 每日一抽按日期记
- `stars` 寻星成绩，按角色分别记

旧版分开存的 `lol1:favs` / `lol1:starhunt` 会在首次运行时自动迁移并删除。

站点没有后端，所以这些数据**只在这台设备上**；无痕模式下写入会失败，
`store.js` 退回内存态，功能降级但不报错。

## 每日一抽的取法

用日期做确定性种子（`daily.js`），同一天任何人进来看到的都是同一位，跨天才换。

真随机意味着刷新一次换一个，反而没有"今天是她"这件事。
实测 365 天覆盖全部 12 位，最多 44 次最少 21 次（理想 30.4），分布合理。

日期取**浏览器本地时区** —— 没有后端可依，统一时区反而会让某些人的
"今天"对不上。

## 性格测试怎么匹配

七个问题给六个维度加权（温柔/体贴/活泼/安静/好奇/独立），累加成向量后
和 `characters.json` 里的 `traits` 算余弦相似度。

用余弦不用欧氏距离：它只看"偏好形状"，不看答题总量 ——
有的选项给 3 分有的给 2 分，总量本来就不该影响结果。

改 `traits` 时要验证 12 人是否都能被测出来。第一版有 2 人永远测不到
（雪乃被书织遮住、云雀被夜宵遮住，画像太像），调整后才 12/12 可达。

### 性能与降级

3D 相关代码**全部动态 import**，首页不含 three.js：

- `navigator.connection.saveData` 或 `effectiveType` 为 `2g/slow-2g` → 不下载 three.js，直接走图片模式
- 无 WebGL 上下文 → 同上
- 模型加载失败 → 回落到该角色的 2D 插画，页面不空白

能力探测放在独立的 `capability.js` 里（不 import three），否则 ES module 一加载就会把整个 three 拉下来，降级就失去意义了。

### 模型流水线

模型来自 Hunyuan3D 2.1，走 ComfyUI 侧的美化流程，再用 `scripts/3d/prepare-model.mjs` 做离线处理：

```bash
node scripts/3d/prepare-model.mjs in.glb out.glb
```

导出格式要点：glTF 磁盘坐标系。

> ⚠️ Blender 里看到模型「Z 轴朝上」是 glTF 导入器的 Y-up→Z-up 转换结果，**不是文件本身的朝向**。
> 文件内部实测已是 Y-up（Y span 1.96 / X 1.45 / Z 0.90），千万别在运行时再加 `rotation.x = -π/2`，否则会躺倒。

运行时只需要：居中 → 脚底对齐 `y=0` → 缩放到 1.8 世界单位（见 `rig.js`）。

个别模型的默认朝向不统一，用 `characters.json` 的 `modelYaw`（度）单独修正，目前 `umi=90`、`kanon=270`。

### 当前模型覆盖

12 位角色全部有 3D 手办，没有走立牌降级的。

`chacha` 和 `suzuka` 一度做不出来 —— 它们原有的插画不适合建模：

- `chacha` 是**坐姿**，人和椅子、餐桌长在一起，Hunyuan3D 分不开，转起来是一团；
- `suzuka` 被猫、南瓜、货架围住，人和道具连成一片，剪出来满身挂件。

**解法不是调参数，是把「给人看的插画」和「给机器看的构图板」分开。**

`characters.json` 里新增 `modelSource` 字段，指向一张单独的构图板
（`assets/img/refs/<id>.webp`）。这张图只服务建模：站姿、正面、四肢分开、
纯白背景、没有任何会挡身体的道具。站点插画完全不动，视觉一致性不受影响。

构图板由 `scripts/3d/gen-reference.mjs` 出，用的是跑通 Anima 插画的同一套参数：

```bash
node scripts/3d/gen-reference.mjs chacha --n=6   # 出 6 张候选挑一张
node scripts/3d/gen-reference.mjs --all
```

### 构图板的两个要点

1. **脸必须露出来**。第一版没加约束，刘海盖住眼睛，模型推不出五官起伏，
   出来是一团面片。提示词里补 `clear facial features, visible eyes,
   no hair covering eyes` 后正常。
2. **顶点预算按角色调**。默认 36k 顶点对简单角色够用，但这两位裙摆/帽檐结构
   复杂，36k 时脸会塌成碎面。用 `TARGET_VERTS=120000` 重跑后明显改善
   （茶茶 240KB、铃鹿 300KB，仍在合理范围）。

### 让模型不塌的三个预处理

插画直接喂给 Hunyuan3D，很容易生成「一坨」。踩过三次，都固化成了脚本：

1. **抠图后裁主体**（`isolate-subject.mjs`）
   BiRefNet 会把悬空道具也当主体抠出来（hibari 的发簪、风铃），
   生成后道具悬在头顶，包围盒被撑高，前端归一化时人物缩到角落 ——
   看着像「头身分离」。做法是取最大连通域，其余刷白，再把人物框满画布。

2. **切背景板**（`trim-backdrop.mjs`）
   插画里人物身后常有装饰背板（拱门、橱窗）。模型是正视投影，板会被挤成
   一层薄壳挂在背后，怎么转都不像手办。做法是按 Z 分 24 层统计投影面积，
   删掉「贴边且面积远超平均」的层 —— 实测背景板会独占约一半投影面积。

3. **换 seed**
   `cream` 用 seed 1011 出来是糊的，seed 7 就完整了（厨师帽、托盘都在）。
   `HUNY_SEED=7 node scripts/3d/prepare-model.mjs cream` 即可重跑。

### 着色

不上 PBR 贴图，改用「素色手办」方案：单色纵向渐变 + 反向外壳描边 + 三点布光。
好处是不用依赖生成模型的 UV，侧转到背面也不会露出贴图接缝。

渐变的颜色由 `characters.json` 的 `palette` 推导，并压低了明度——直接用 UI 的浅色当底色会白成一片、看不清体积。
