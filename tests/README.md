# 测试

```bash
npm test          # 全部（约 2 分钟）
npm run test:fast # 页面冒烟 + 数据校验（约 40 秒）
npm run test:data # 纯数据，不起浏览器（约 1 秒）
```

首次运行会自动在 `.cache/pyenv/` 建虚拟环境并装依赖，换机器不用手动装。
需要 `python3` 和 `node`；无显示器环境会走 `xvfb-run`。

## 这些测试为什么存在

不是"为覆盖率写测试"。每一条都对应一次真出过的问题，或者一类
"错了也不报错"的静默失败。

| 文件 | 挡住什么 |
| --- | --- |
| `test_pages.py` | 页面打不开、横向溢出、JS 报错、**导航顺序不一致**、主题切换失效 |
| `test_data.py` | 数据字段缺失、关系指向不存在的人、**角色永远测不出来** |
| `test_crosscheck.py` | JS 与 Python 两份算法算出不同结果 |
| `test_store.py` | 存档迁移丢数据、坏存档白屏、隐私模式下崩溃、清空不可逆 |
| `test_play.py` | 测验走不完、配对判定错、玩法切换页头不同步 |
| `test_css.py` | **引用了不存在的 CSS 变量**、括号不配对、暗色主题漏定义 |
| `test_a11y.py` | 图片缺 alt、按钮无名、焦点不可见、无障碍状态不同步 |

## 三条踩过的坑

**CSS 变量写错不会报错。** 有一版用了 8 处 `var(--ink-1)`，这个变量不存在，
`color-mix()` 整体失效，进度条轨道直接消失。页面不报错、不溢出、JS 也没事，
浏览器测试全绿。所以 `test_css.py` 直接读源码做静态检查。

**平局处理不一致。** JS 用 `if (s > best)` 严格比较（并列取先出现的），
Python 的 `max([(sim, i)])` 在并列时按第二元排序（取后出现的）。
同一道题算出两个结果。`test_crosscheck.py` 让 Node 真跑一遍线上逻辑对答案。

**一次挂多个 dialog handler 会互抢。** 第二次点击时两个 handler 都触发，
报 "already handled"。改成单个 handler + 可变标志。

## 不做的事

**不做像素级视觉回归。** 字体渲染在不同机器上差几个像素就会红，
产出的噪音远大于它能发现的问题。视觉靠人看，逻辑靠测试。

**不做覆盖率统计。** 数字好看和测试有用是两件事。
